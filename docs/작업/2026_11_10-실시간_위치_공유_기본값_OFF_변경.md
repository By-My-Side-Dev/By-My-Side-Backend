# 실시간 위치 공유 기본값 OFF 변경

## 1. 개요 및 배경
- 이슈: #117. 브랜치: `fix/#117-realtime-location-default-off`.
- 앱 사용자가 직접 실시간 위치 공유를 켜도록 신규 가입 기본값을 false로 변경한다.

## 2. 관련 구현 및 현행 분석
- 일반·소셜 가입은 SignupService에서 User.builder()로 신규 계정을 생성한다.
- 기존 기본값은 User 필드와 Flyway 컬럼 기본값 모두 true다.
- UserController → UserService → User.updateRealtimeLocationEnable로 설정을 변경한다.
- 소셜 계정 연결은 기존 User를 사용하며 공유 설정을 변경하지 않는다.

## 3. 설계 및 구현 계획
- User 초기값과 신규 Flyway 컬럼 기본값을 false로 맞춘다.
- 기존 사용자 데이터와 지인별 receiveRealtime 설정은 유지한다.
- UserController OpenAPI, user-profile OpenSpec과 마이그레이션 운영 문서를 갱신한다.
- 가입 서비스 테스트에서 일반·소셜 가입 OFF 및 기존 계정 소셜 연결 시 ON 유지 여부를 확인한다.

## 4. 트레이드오프 및 고려사항
- 신규 가입자는 앱에서 명시적으로 켜야 후속 실시간 위치 갱신이 가능하다. 최초 호출 위치 제공은 기존과 같다.
- DB 기본값만 변경하면 JPA가 명시적으로 true를 저장하므로 엔티티와 함께 변경한다.
- 기존 계정 일괄 갱신은 사용자 선택을 덮어쓰므로 수행하지 않는다.
- OS 위치 권한은 앱에서 별도로 확인한다. 새 테이블이나 추상화는 추가하지 않는다.

## 5. 검증 계획
- 변경 전 일반·소셜 가입의 false 단언 실패를 확인하고 변경 후 재실행한다.
- 가입·현재 긴급호출·만료 관련 회귀 테스트 및 빌드를 실행한다.
- Docker 실행 후 MySQL 8.4의 세션 전용 임시 users 테이블에 실제 마이그레이션 파일을 실행했다. 기존 true/version=7, false/version=9 보존 및 기본값 생략 INSERT의 false/version=0을 확인했고 검증 결과는 PASS다. 실제 users 테이블은 변경하지 않았다. 전체 Flyway 실행 검증은 별도다.
- 검증 결과: 변경 전 가입 테스트 3개 중 신규 일반·소셜 가입 기본값 단언 2개 실패, 변경 후 가입·비밀번호·현재 호출·만료 테스트 총 23개 통과 및 bootJar 성공. git diff --check 통과.
- 배포 전 추가 검증: 별도 MySQL 스키마에서 `clean test bootJar --no-daemon` 전체 테스트 24개 통과. local 프로필로 스키마 생성 후 직전 버전 20261024.01을 baseline으로 설정하고 prod 프로필 JAR를 기동해 신규 Flyway 20261110.01 적용 및 Hibernate validate 성공, `/health` UP을 확인했다.
- 실제 HTTP 로그인·프로필 기본값 OFF·설정 ON/OFF 모두 통과했다. 실제 테이블에서 기존 true/version=7 및 false/version=9 보존, 기본값 생략 신규 INSERT의 false도 PASS다. 운영 데이터는 접근하지 않았다.
